# 学习规范：教学与产品共用同一套方法论

这份文档同时约束两件事：

1. 我怎么教你搭建这个系统。
2. 这个系统本身长成什么样。

原则很简单：**怎么教你，就怎么设计功能；怎么设计功能，就怎么教你。**

---

## 0. 两条线

- **教学线**：按「一个请求的完整旅程」搭主干，一层一层往上挂知识。
- **产品线**：平台强制你「先定义问题 → 再执行 → 再验证 → 最后输出」。

两条线不是两套东西，而是同一套方法论的两种用法。

---

## 1. 四条方法论

### 1.1 一条主干

所有知识都挂在同一条链路上：

```text
DNS → HTTP → 网关 → 后端分层 → 数据库 → 大模型调用 → 日志与部署
```

遇到任何新东西，先问：它在这条链路的哪一环？解决什么问题？

### 1.2 验证闭环

“跑通了”不等于“做对了”。每件事至少做到：

1. 修复前能复现问题
2. 修复后同一个输入不再出错
3. 相关功能回归通过
4. 能向别人讲清改了什么、为什么改、影响哪里

讲不清的代码不提交。

### 1.3 用 AI 学，不让 AI 替你学

固定四步：

1. **先自己想**：独立想 10 分钟，把思路写下来，哪怕是错的。
2. **再问 AI**：让它解释原理、比较方案，不要直接要代码。
3. **关掉 AI 复现**：合上对话，自己从头写一遍；卡住的地方就是没懂的地方。
4. **用自己的话讲出来**：写成笔记或讲给别人听。

### 1.4 以项目为纲，用输出倒逼输入

- 不按课程清单学，按项目需要学。
- 每阶段留下一件能讲透的产物。
- 每周写一篇笔记，只写这一周真正弄懂的一件事。

---

## 2. 讲解协议（每次固定 8 步）

1. **定位**：现在在知识主干的哪一环，上一层是什么，这一环解决什么问题。
2. **问题**：先讲“不这样做会怎样”，再讲方案。
3. **概念**：只引入一个新概念，一句话定义。
4. **机制**：内部怎么运转，必要时画数据流。
5. **代码**：对应项目里的文件、函数、关键几行。
6. **验证实验**：给一个关掉 AI 能自己完成的小实验，你亲手做。
7. **串链**：接回上一层，说明输入和输出。
8. **输出与自测**：你用五问写一段笔记，再回答 2 个问题；确认后才进入下一层。

硬性规则：

- 一次只加一层，不跳层。
- 术语第一次出现必须解释。
- 每层结束更新累积图。
- 不为了全面而堆内容；一层讲透再往下。
- 你说「继续」才推进。

---

## 3. 你的动作（每层都要做）

- 讲概念前，先自己写 3–5 行理解。
- 讲代码时，跟着指出每一行在主干上的位置。
- 每层结束，关掉 AI 独立复现一次。
- 用五问写输出：

```text
做了什么 / 为什么这样做 / 怎么验证的 / 还有什么风险 / 下一步做什么
```

## 4. 产品功能原则

平台不是普通待办清单，它要逼着使用者走完方法论。

| 方法论 | 产品里对应的功能 |
|---|---|
| 一条主干 | 「知识主干」页：DNS/HTTP/网关/后端/数据库/大模型/日志 七个检查点 |
| 先定义问题 | 任务开始前填：解决谁的问题、验收标准、最小可用版本 |
| 验证闭环 | 验证式打卡：复现方式、回归结果、能否讲清、证据链接 |
| AI 四步 | 任务内置四步清单：先想 / 问原理 / 关 AI 复现 / 讲出来 |
| 输出倒逼输入 | 每周笔记 + 五问复盘，可导出 |
| 阶段产物 | 「路线」页：阶段目标与作品集 |
| 不堆功能 | 每阶段只加支撑方法论的字段，不加“看起来很全”的模块 |

判断一个功能要不要做，只问一句：**它是否让上面某条方法论更容易被执行？**

---

## 5. 知识地图

依赖顺序从上到下，每一层都建立在上一层之上。

| 层 | 要回答的问题 | 核心概念 | 项目对应 |
|---|---|---|---|
| L1 运行与通信 | 两个程序怎么互相说话 | 进程、端口、HTTP、JSON、代理 | `vite.config.ts`、`app/main.py` |
| L2 数据建模 | 一件事怎么变成表和关系 | 实体、主键、外键、一对多 | `models.py`、迁移文件 |
| L3 SQL 与事务 | 多条写操作怎么保持一致 | SELECT/INSERT/UPDATE、事务、原子性 | `service.complete_plan_item` |
| L4 ORM 与迁移 | Python 对象怎么变成表 | ORM、Session、Unit of Work、迁移 | `shared/db.py`、`alembic/` |
| L5 后端分层 | 一个请求经过哪些层 | router、schema、service、依赖注入 | `api/learning/`、`service.py` |
| L6 HTTP 接口设计 | 资源怎么映射成 URL 和方法 | REST、状态码、幂等 | `plans.py`、`goals.py` |
| L7 前端渲染 | 数据怎么变成界面 | 组件、state、事件、渲染 | `Today.tsx` |
| L8 前端数据同步 | 服务端数据怎么保持最新 | 查询缓存、mutation、失效、重取 | `api/learning.ts` |
| L9 工程验证 | 怎么知道改动没弄坏 | 测试隔离、类型检查、构建 | `tests/`、`ruff`、`tsc` |

### 主干实验清单（关掉 AI 做）

| 环节 | 实验 | 做完能回答 |
|---|---|---|
| DNS | `nslookup` 查域名，改一次 hosts | 域名怎么变成 IP |
| HTTP | `curl -v` 请求公开接口 | 401/403/404/500 分别说明什么 |
| 网关 | 本机装 Nginx 反向代理到本地服务 | 请求怎么转到后端 |
| 后端分层 | 手写 Controller/Service/Mapper 增删改查 | 每层该放什么 |
| 数据库 | 加索引，前后各看一次 `EXPLAIN` | 索引为什么快、何时失效 |
| 大模型 | 直接用 HTTP 调一次模型，要求返回 JSON | 提示词、上下文、结构化输出 |
| 日志部署 | Linux 启动服务，故意制造报错并查日志 | 进程、端口、日志在哪 |

## 6. 阶段路线（按读研节奏）

| 阶段 | 时间 | 平台要做的 | 你要产出的 |
|---|---|---|---|
| 休整与复盘 | 现在到春节 | 阶段 1.5：验证式打卡 + 五问复盘 | 两个项目复盘、一张知识主干图 |
| 打地基 | 接下来一学期 | 阶段 2–4：登录、Docker、AI 计划、看板、知识主干 | 完整可用的平台 + 每周笔记 |
| 定方向 | 读研第一年 | 阶段 5–6：AI 复盘、每周输出、部署 | 一段实习、对方向的判断 |
| 做深 | 读研第二年 | 课程笔记 / RAG / 作品集导出 | 一件经得起深挖的代表作 |
| 求职 | 毕业前一年 | 作品集与复盘导出 | 能讲清的项目与简历 |
